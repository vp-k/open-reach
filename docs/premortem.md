# Pre-mortem — open-reach

> **전제**: 오늘로부터 6개월 뒤, 이 프로젝트는 실패했다. 부검을 하라.
> Phase 0 Step 0-7 산출물. 각 Tiger는 Phase 전환 게이트에서 해소 여부를 검사받는다.

작성: 2026-08-24 · 자체 분석 + 외부 검토(codex, CRITICAL 15 / MAJOR 16 / MINOR 2) 병합

---

## Tiger 목록

> Tiger = 방치하면 프로젝트를 죽이는 위험. 각 항목은 **어떤 관측이 나오면 발동한 것으로 판정하는지**를 함께 적는다.

### T-1. 배터리가 자기 채점표가 된다 (CRITICAL)

**사망 시나리오.** 돌파율이 North Star이므로, 수치를 올리는 가장 싼 방법은 엔진 개선이 아니라
**배터리에 잘 열리는 URL을 더 넣는 것**이다. 6개월 뒤 돌파율 92%인데 실제 리서치에서는 여전히 막힌다.

**왜 지금 문서가 못 막나.** SC-2는 "Tier-1 ≥ 80%"라고만 하고, Tier-1의 **구성 요건**이 없다.

**해소 조건 (overview.md "배터리 거버넌스" G-1~G-7로 반영 완료, SPEC에서 강제)**
- G-1~G-7: 벤더 9종 × 최소 2, T1 미돌파 최소 1/3, 음성 케이스 필수, `expected` 필수,
  교체 이력 보존, Tier-1 상한 50, holdout 격리.
- `battery_hash`가 달라진 실행은 **회귀 비교 대상에서 제외**한다 (사과 vs 오렌지 차단).
- 벤치 출력은 `by_vendor`/`by_route`/`by_reason` 분해를 **항상** 동반한다. 한 벤더라도 50% 미만이면
  전체 수치와 무관하게 SC-2 fail.
- **holdout(SC-6)이 최종 방어선이다.** 배터리를 아무리 다듬어도 개발 중 보지 않은 URL 집합의
  낙폭이 15%p를 넘으면 릴리즈가 막힌다.

### T-2. A1이 거짓이어서 R2가 통째로 헛수고 (CRITICAL)

**사망 시나리오.** curl_cffi TLS 임퍼소네이션만으로는 주요 WAF가 거의 안 뚫린다.
R2에 두 달을 쓴 뒤에야 "결국 브라우저 없으면 안 된다"를 알게 된다.

**해소 조건**
- ADR-001의 역순 개발이 이미 대응이다. **R1 종료 시점에 A1 실측 수치를 반드시 보고**하고,
  Tier-1에서 T1 단독 돌파율이 **40% 미만이면 R2 범위를 축소하고 R3(브라우저)를 앞당긴다**.
- 이 판정을 문서가 아니라 벤치 출력의 `by_route` 항목으로 자동화한다.

### T-3. 원본 대조가 시작도 못 하고 끝난다 (MAJOR — 반영 완료)

**사망 시나리오.** SC-1은 원본을 로컬에서 실행할 수 있어야 성립한다. 원본이 Python 의존성
충돌·API 키 요구·플랫폼 미지원 등으로 우리 환경에서 안 돌면 SC-1은 처음부터 측정 불가다.
그런데 그 사실을 R3(대조 러너)에 가서야 알게 된다.

**해소 조건 (반영 완료)**
- **원본 대조 러너를 R1로 앞당겼다.** 원본이 MIT인 창이 열려 있는 동안에만 가능한 측정이다.
  R1 착수 직후 원본 실행 가능성부터 확인한다 (스파이크, 반나절 상한).
- **SC-1을 지속 게이트에서 "R1 한정 게이트"로 강등했다.** codex 지적대로, 실행 조건(원본 commit SHA,
  일시, OS, 네트워크)이 함께 동결되지 않은 "마지막 원본 수치"는 재현도 비교도 불가능하다.
  따라서 이후 릴리즈 판정에서 SC-1은 제외되고 **SC-2 + SC-6(holdout)** 이 지속 기준을 담당한다.
- 실행 불가로 판명되면 SC-1은 즉시 `측정 불가`로 마킹된다 (overview.md "판정 규칙의 소멸 대비").

### T-4. 경계(NG-1/NG-2)가 말뿐이 된다 (CRITICAL)

**사망 시나리오.** 로그인월 감지가 휴리스틱이라 오작동한다. "로그인 유도 배너가 있지만 본문도
있는" 페이지에서 계속 폴백을 상승시키다가, 결과적으로 페이월 뒤 콘텐츠 일부를 긁어 온다.
공개 플러그인이므로 이 사고는 곧바로 평판·법적 문제다.

**해소 조건**
- 경계 판정을 **엔진 옵션이 아니라 파이프라인 불변식**으로 구현한다:
  `auth_wall`/`paywall` 판정 시 상위 티어 진입 함수가 호출 자체를 거부한다 (fail-closed).
- SC-3(오탐 0)을 **양방향**으로 만든다. 현재는 "월을 성공으로 보고" 만 금지한다.
  배터리에 **의도적 로그인월/페이월 URL을 넣고, 반드시 `auth_wall`/`paywall`로 분류되는지**
  검사하는 음성 케이스를 Tier-1에 포함한다. 이 케이스가 실패하면 벤치 전체를 fail로 만든다.
- 인수 테스트에 "폴백 상승 금지" 케이스를 동결한다.

### T-5. 유지 주체가 1명이고, 분기 리프레시가 돌지 않는다 (MAJOR)

**사망 시나리오.** SC-5(자동 갱신)는 `refresh` 명령을 **누군가 실행해야** 성립한다.
3개월 뒤 아무도 실행하지 않고, 지문표는 원본에서 시드한 그대로 낡는다.
원본을 안 쓰기로 한 이유가 그대로 재발한다.

**해소 조건**
- `last_reviewed` 날짜를 프로파일에 두고, **벤치 실행 시 90일 초과분을 경고로 출력**한다.
  (관측 → 경고 → 사람 실행. 완전 자동화는 범위 밖이지만, 침묵은 막는다.)
- 돌파율이 이전 실행 대비 dead-band 밖으로 떨어지면 `refresh` 제안을 출력에 포함한다.

### T-6. 브라우저 의존성이 설치 경험을 망친다 (MAJOR)

**사망 시나리오.** P2 사용자가 첫 `fetch`에서 400MB 다운로드를 만나고 플러그인을 지운다.
또는 CI/헤드리스 환경에서 Playwright가 깨져 플러그인 전체가 실패한 것처럼 보인다.

**해소 조건**
- ADR-004의 지연 설치 + 사전 고지가 1차 대응.
- **T1 단독 모드가 언제나 완전히 동작해야 한다.** 브라우저 설치 실패는 `fetch` 실패가 아니라
  `unsupported: browser_required`라는 **정상적인 분류 결과**로 처리한다 (SC-4).
- 벤치는 `--no-browser` 수치를 항상 함께 보고한다 (ADR-004 결과 절).

### T-7. "리서치 도구"가 "우회 도구"로 읽힌다 (MAJOR)

**사망 시나리오.** 공개 마켓플레이스에 올라간 뒤, 설명이나 배터리 내용 때문에 특정 사이트
차단 우회 도구로 인식된다. 신고·삭제 요청·평판 손상.

**해소 조건**
- P2(사이트명 금지)와 NG-9가 1차 방어. 배터리 URL은 저장소에 남지만 **README/SKILL.md 어디에도
  사이트 이름을 지원 목록으로 광고하지 않는다** (NG-8).
- `docs/policy-boundaries.md`를 Phase 1 필수 산출물로 만든다: robots/ToS 존중 방침,
  단건 조회 한정(NG-5), rate limit 존중(NG-6), 인증정보 미취급(NG-4)을 명문화하고
  README 최상단에서 링크한다.
- A7(High, 미검증)의 검증 산출물이 곧 이 문서다.

### T-8. 계측기가 R1에서 끝나지 않고 R1이 끝없이 늘어난다 (MINOR)

**사망 시나리오.** 배터리 큐레이션·검증기 정교화에 빠져 R1이 두 달이 된다. 엔진은 시작도 못 한다.

**해소 조건**
- R1의 종료 조건을 **산출물이 아니라 보고서 1장**으로 정의한다:
  "Tier-1 N개 URL에 대해 현재 돌파율 X%, 벤더별 분해, 원본 대비 Y%" 가 출력되면 R1 종료.
- Tier-1 규모 상한을 SPEC에 명시한다 (예: 30~50 URL). 더 넣고 싶으면 Tier-2로 간다.

### T-9. "성공"의 정의가 느슨해 수치가 부풀려진다 (CRITICAL · codex)

**사망 시나리오.** 오류 페이지·검색 결과·동의 배너·기사 첫 문단·soft paywall 미리보기를
"본문 추출 성공"으로 세면, 돌파율은 높은데 실제로는 아무것도 못 읽는다.
T-1(배터리 조작)보다 더 조용히 진행된다 — 배터리를 안 건드려도 발생한다.

**해소 조건 (반영 완료)**
- North Star를 "본문 추출 성공"에서 **"기대 정답 대조 통과"** 로 재정의.
- 각 `BatteryEntry`는 `expected`(제목·핵심 문자열·최소 길이·정규화 해시)를 필수로 갖는다 (G-4).
- 기대 정답을 정의할 수 없는 URL은 배터리에 넣지 않는다.
- 판정이 애매하면 `validation_failed`로 **보수적으로 실패 처리**한다. 성공은 고신뢰일 때만.

---

### T-10. SSRF — 임의 URL fetch가 내부망 통로가 된다 (CRITICAL · codex)

**사망 시나리오.** 이 도구는 LLM이 부르는 CLI다. 프롬프트 인젝션이나 실수로
`http://169.254.169.254/...`, `http://localhost:8080/admin`, 사내 IP가 전달되면
브라우저 티어까지 동원해 **성실하게 가져온다.** 공개 플러그인이므로 피해 범위가 사용자 전체다.

**해소 조건 (NG-11로 신설)**
- 스킴 allowlist(http/https), DNS 해석 후 사설·루프백·링크로컬·CGNAT·메타데이터 주소 차단.
- **리디렉션 매 홉마다 재검사** (초기 URL만 검사하면 우회된다).
- `policy_blocked` 사유로 보고. 이 가드는 **R1에 구현한다** — 브라우저가 오기 전에 있어야 한다.

---

### T-11. 관측 로그와 브라우저가 NG-4를 무력화한다 (CRITICAL · codex)

**사망 시나리오.** URL query에 담긴 개인식별 파라미터, 리디렉션 URL, `Set-Cookie` 헤더,
Chromium 프로필·캐시가 로그와 디스크에 남는다. "자격증명 미취급"은 선언만 남고,
사용자의 리서치 주제 이력까지 장기 보관된다.

**해소 조건 (NG-4 강제 수단 + ADR-004 개정으로 반영)**
- 브라우저는 **매 실행 임시 프로필**, 종료 시 삭제. 사용자 기존 프로필 접근 금지.
- 관측 로그 URL은 **scheme+host+path만** 저장 (query·fragment 제거).
- 쿠키·`Authorization`·`Set-Cookie`는 기록하지 않는다 — **금지 필드 화이트리스트 테스트**로 강제.
- 본문은 디스크에 캐시하지 않는다 (NG-12).

### T-12. `refresh` 자동 학습이 정책 위반을 학습한다 (CRITICAL · codex)

**사망 시나리오.** SC-5의 자동 갱신은 "돌파율이 오르는 방향"으로 후보를 재정렬한다.
그런데 돌파율을 올리는 경로 중에는 경계에 걸친 것(soft paywall 미리보기를 성공으로 오판,
rate limit 무시)이 섞일 수 있다. 피드백 루프가 **위반을 강화하는 통로**가 된다.

**해소 조건**
- `refresh`의 학습 입력에서 **경계 관련 관측을 제외**한다: `auth_wall`/`paywall`/`policy_blocked`/
  `rate_limited`로 분류된 시도는 후보 점수에 반영하지 않는다.
- `validation_failed`도 학습 입력에서 제외한다 (기대 정답 미달을 성공으로 학습하지 않게).
- SC-5 합격선에 **"갱신 diff가 경계 위반 관측을 포함하지 않을 것"** 을 포함했다.
- `refresh` 결과는 자동 적용이 아니라 **diff 출력 + 명시적 적용**으로 한다.

### T-13. R1이 아무 수치도 못 낸다 (CRITICAL · codex — 반영 완료)

**사망 시나리오.** 초안의 R1은 계측기만 있고 엔진이 없었다. `bench`가 통과시킬 대상이 없어
돌파율이 산출되지 않고, A1 검증도 R2로 밀린다. "엔진에 투자하기 전에 A1을 실측한다"는
역순 개발의 취지가 스스로 무너진다.

**해소 조건 (ADR-001 개정 · 반영 완료)**
- R1에 **baseline transport + 벤더 라벨링 최소 구현 + 본문 추출 + 정책 가드 + 원본 대조**를 편입.
- R2는 "엔진 제작"이 아니라 **"측정되는 엔진의 최적화"** 로 재정의.

## 실패 원인 Top 3 (요약)

1. **지표가 현실에서 분리된다** — 배터리 조작(T-1) + 느슨한 "성공" 정의(T-9)가 겹치면
   돌파율 90%인데 실제 리서치는 그대로 막힌다. 방어: 기대 정답 대조 + 거버넌스 + holdout(SC-6).
2. **경계가 선언에 그친다** — 로그인월 오판(T-4), SSRF(T-10), 인증정보 유출(T-11),
   위반 학습(T-12). 공개 플러그인이라 사고 한 건이 곧 배포 중단이다.
   방어: 모든 NG에 강제 수단 명시(P7) + 정책 가드를 R1에 배치.
3. **A1/A2 오판으로 방향을 못 바꾼다** — 벤더 일반화가 안 되는데 브라우저를 강화하며 버틴다.
   방어: `by_route` 임계값(40%)과 holdout 낙폭(15%p)을 **전환 트리거로 사전 정의**.
   실패 시 대응은 "더 뚫기"가 아니라 **"지원 범위 축소 또는 제품 재정의"** 다.
