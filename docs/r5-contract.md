# R5 계약 — insane-search 파리티 (Phase 0 어댑터 확장 + Phase 1 리더 폴백)

> 이 문서는 R2 계약(`r2-contract.md`)·R3 계약(`r3-contract.md`)과 같은 지위의 **라운드 계약**이다.
> R5의 범위·경계·측정 근거·종료 조건을 고정한다. SPEC의 US-B-012~014와 AC-B-008-1 개정이
> 이 계약을 구현 계약으로 승계한다.

## §1 배경 — 사용자 관찰과 근본 원인

사용자 관찰: **"insane-search는 네이버 검색이 되는데 open-reach는 설명상 안 되는 것 같다."**

근본 원인 (코드 실측, 2026-09-02):

| 티어 | insane-search | open-reach 현재 |
|------|---------------|-----------------|
| Phase 0 (플랫폼 엔드포인트) | X·Reddit·Threads·Bluesky·Mastodon·Naver·HN | **`api_index.yaml` 1건**(stackoverflow.com)뿐 |
| Phase 1 (URL 변형 + Jina Reader) | 있음 | **미구현** (`SUPPORTED_VARIANTS=("original",)`, Jina 없음) |
| Phase 2 (curl_cffi TLS) | 있음 | 있음 |
| Phase 3 (브라우저) | 있음 | 있음(R3, us-b-011 동결) |

즉 open-reach는 Phase 2/3(차단 우회)만 갖췄고, **플랫폼이 스스로 공개한 문**(Phase 0)과
**일반 리더 폴백**(Phase 1)이 비어 있다. 네이버·스레드·레딧 같은 플랫폼 도달은 원본에서
Phase 0/1이 만드는 것이므로, open-reach가 못 하는 것은 정확한 관찰이다.

R5 목표: **공개 접근 가능한 범위에 한해** insane-search와 플랫폼 도달 파리티를 확보한다.
사용자 결정 근거: "둘 다 (원본 파리티 목표)" + "권고안대로 진행해" (2026-09-02).

## §2 측정 근거와 R2 배제의 재조정 (⚠ 근거 정합성 핵심)

R2 계약은 "URL 변형"을 **명시적으로 배제**했다 (SPEC Round 경계, r2-contract §2·§5):

> 성공 표본 8곳의 `<link rel="amphtml">` 선언 0건, 차단 4곳 × 변형 3종 회피 **0/12**
> (`m.` 호스트는 4곳 전부 DNS 부재). 지문표의 미실행 `mobile` 선언도 함께 제거한다 (NG-10).

이 실측은 **WAF로 차단된 일반 사이트 4곳에 `m.`/`amp` 접두를 붙여 우회**하는 실험이었고 0이었다.
R5는 이 결론을 **뒤집지 않는다.** 다음을 구분한다:

- **맹목적 변형 확장기** (임의 차단 URL에 `m.`/`amp`를 부착해 우회 시도) — R2가 0/12로 배제. **R5도 부활시키지 않는다** (NG-10: 없는 돌파를 지어내지 않는다).
- **플랫폼이 스스로 공개한 피드/엔드포인트** (reddit `{permalink}.rss`, HN Algolia, Bluesky AT Protocol, Naver 검색) — 이는 "차단 우회"가 아니라 J1의 **"열린 문"**이다. R2 실측이 다룬 질문이 아니다.
- **Jina Reader** (`r.jina.ai`) — 변형이 아니라 **제3자 리더 게이트웨이**. 별도 opt-in으로 취급.

**결론 — R5의 Phase 1/Phase 0 재정의:**

1. **Phase 0 어댑터가 R5 파리티의 주 레버다.** 기존 `api_index.yaml` 메커니즘(US-B-010, 2-hop 포함)을
   재사용해 공개 확인된 플랫폼 엔드포인트를 인덱스 항목으로 추가한다. 각 항목은
   `source`(공식 문서) + `verified_at`(직접 200 확인일) 의무, 20항목 상한(AC-B-010-15)을 그대로 진다.
2. **Phase 1은 "맹목적 변형 확장"이 아니라 Jina Reader opt-in 폴백으로 좁힌다.** 프로파일이
   선언하고 `verified_at`을 가진 변형만 라우팅하며, R2가 배제한 접두 부착 확장기는 도입하지 않는다.
3. 따라서 `SUPPORTED_VARIANTS` 확장은 **인덱스/프로파일 선언에 종속**되며, 선언 없는 URL에
   변형을 시도하지 않는다.

## §4 경계 결정 3건 (사용자 승인 2026-09-02 "권고안대로 진행해")

### ① 검색 결과 = 본문 아님 충돌
`AC-B-008-1`은 "검색 결과" 페이지를 `validation_failed`로 분류한다. 그러나 Naver 어댑터는
검색 결과 페이지를 반환한다. **해소**: 사용자가 **명시적으로 검색 결과 URL을 준 경우**에만
결과 목록을 유효 본문으로 인정한다. 임의 URL에서 우발적으로 나온 검색 페이지는 여전히
`validation_failed`. → AC-B-008-1 개정 + US-B-014.

### ② Jina Reader = 제3자 경유
`r.jina.ai`는 우리 대신 대상을 가져온다(본문이 제3자를 경유). **해소**: opt-in 플래그
`--allow-reader`로만 활성. 기본 비활성. 정책 계층에 문서화. **사설/비공개 URL을 리더에
전송하지 않는다**(기존 SSRF 가드 재사용 — 리더 URL 조립 전 원본 URL을 SSRF 검사). → US-B-013.

### ③ Threads/X 인증월 (NG-1 충돌)
원본의 `video_versions`/신디케이션은 종종 로그인 게이트 뒤에 있다. **해소**: **공개 접근
가능한 콘텐츠만** 어댑트한다. 로그인 필요 콘텐츠는 계속 감지·보고(`auth_wall`, 종료 코드 2)하며
우회하지 않는다(NG-1). 원본과 **의도적으로 분기**한다(NG-10). → US-B-012 AC.

## §5 어댑터 후보와 공개성 검증 의무

각 후보는 인덱스 등재 전에 **직접 200 확인**을 거치고 `verified_at`을 남긴다. 공개성이
확인되지 않거나 인증을 요구하면 **등재하지 않는다**(NG-8: 배터리에 없는 사이트를 지원으로 표기 금지).

| 플랫폼 | 공개 엔드포인트(후보) | 인증 필요 | 비고 |
|--------|----------------------|-----------|------|
| Naver 통합검색 | `search.naver.com/search.naver?query=…` | 공개 | 경계①(명시적 검색 URL)로 본문 인정. TLS 임퍼소네이션은 Phase 0에서 금지(AC-B-010-4)이므로 curl_cffi 경로와의 배치 결정 필요(§6) |
| Reddit | `{permalink}.rss` | 공개 | `.json`은 현재 403 → 미등재 |
| Hacker News | `hn.algolia.com/api/v1/search?query=…` / items | 공개 | 정직한 UA 그대로 |
| Bluesky | `public.api.bsky.app/xrpc/app.bsky.feed.getPostThread` | 공개 | AT Protocol, 2-hop(핸들→DID) 가능성 |
| Mastodon | 인스턴스별 공개 API | 공개 | 인스턴스 호스트 가변 → 인덱스 패턴 검토 |
| Threads(공개 게시물) | 인라인 JSON | 조건부 | 로그인 요구 시 `auth_wall`(경계③) |

⚠ **20항목 상한**(AC-B-010-15)이 강제된다. 위 후보 전부를 넣어도 여유가 있으나, 향후 증식은
상한과 출처 의무로 계속 막는다.

## §6 열린 설계 질문 (구현 대화에서 확정)

1. **Naver 검색의 전송 계층**: Phase 0은 정직한 UA 강제(AC-B-010-4, 임퍼소네이션 금지)인데
   `search.naver.com`은 curl_cffi 임퍼소네이션이 필요할 수 있다. → Naver를 Phase 0 인덱스가 아니라
   **Phase 2(curl_cffi) 위의 어댑터**로 배치하거나, AC-B-010-4에 "검색 엔드포인트 예외"를 두는 대신
   **정직한 UA로 200이 되는 엔드포인트만 등재**(안 되면 미등재, NG-10)로 좁히는 안. **권고: 후자** —
   정직한 UA로 공개되는 것만 Phase 0, 나머지는 지어내지 않는다.
2. **Bluesky 핸들→DID 2-hop**: 기존 2-hop 계약(AC-B-010-8~14)으로 표현 가능한지 실측 확인.
3. **Jina Reader 응답 검증**: 리더가 반환한 마크다운도 US-B-008 검증기(챌린지/동의배너 판별)를
   통과해야 하는가 → **예**(리더가 챌린지 페이지를 그대로 마크다운화할 수 있으므로).

## §7 종료 조건

- US-B-012·013·014의 인수 테스트(고정 픽스처)가 green.
- **`rate_http_only`가 R1/R2 대비 회귀하지 않음** (R2 종료 조건 승계 — Phase 0/1 추가가 HTTP 실력을 가리지 않는다).
- codex 코드 리뷰 open CRITICAL/HIGH 0건.
- 각 어댑터 인덱스 항목이 `source` + `verified_at`을 갖고 20항목 상한 준수.
- 경계 3건이 AC로 배선되고 음성 케이스(우발적 검색 페이지 실패, 인증월 미우회, 리더 SSRF 차단)로 검증됨.
