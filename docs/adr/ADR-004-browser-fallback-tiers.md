# ADR-004: 브라우저 폴백 3단 (curl_cffi → patchright → Playwright real Chrome)

- 상태: Accepted
- 날짜: 2026-08-24
- 관련: A5, A8, P6, NG-4, US-B-001, Round R3
- 개정: 2026-08-24 (codex 검토 [CRITICAL] NG-4 충돌 · [CRITICAL] stealth 정당화 · [MAJOR] 정책 선행 반영)

## 맥락

WAF 챌린지 중 일부(JS 실행을 요구하는 유형)는 HTTP 클라이언트만으로는 원리적으로
통과할 수 없다. 그러나 브라우저는 비싸다 — 최초 1회 150~400MB 다운로드, 회당
수 초의 실행 시간, 메모리. 반대로 브라우저를 아예 안 쓰면 챌린지 유형에서 돌파율이
구조적으로 막힌다.

플러그인 사용자(P2)는 "API 키·로그인·수동 설정 없이 설치만 하면 동작"을 요구한다.
즉 필요할 때 **자동으로** 설치되어야 하되, 무엇을 왜 받는지는 알려야 한다 (P6).

## 결정

**비용 오름차순 3단 폴백. 각 단계는 이전 단계가 명시적으로 실패했을 때만 진입한다.**

| 단계 | 도구 | 비용 | 진입 조건 |
|------|------|------|-----------|
| T1 | curl_cffi (TLS 임퍼소네이션 격자) | ~ms | 항상 먼저 |
| T2 | patchright (patched Playwright) | ~초 + 설치 | T1 전부 실패 AND WAF가 JS 챌린지 유형 |
| T3 | Playwright + real Chrome 채널 | ~초 + 대용량 설치 | T2 실패 AND `allow_browser` 허용 |

- 브라우저 런타임은 **T2 진입 시점에 지연 설치**한다. 설치 전 사용자에게 용량과 사유를 알린다.
- `FetchRequest.allow_browser=false`이면 T1에서 멈추고 `unsupported: browser_required`로 보고한다.
- **어느 단계에서든 로그인월·페이월이 감지되면 즉시 중단한다** (P3, NG-1/NG-2).
  폴백 상승은 "차단"에만 적용되고 "권한 없음"에는 적용되지 않는다.
  이는 옵션이 아니라 **파이프라인 불변식**이다 — 상위 티어 진입 함수가 `auth_wall`/`paywall`
  판정 상태에서 호출되면 예외를 던진다 (fail-closed).

### 인증정보 비접촉 (NG-4 충돌 해소)

브라우저는 본질적으로 쿠키·세션·프로필을 다룬다. NG-4("자격증명 미취급")와 정면으로 충돌하므로
다음을 불변식으로 못박는다.

- **매 실행 임시 프로필**을 생성하고 종료 시 삭제한다. 사용자의 기존 브라우저 프로필을 절대 열지 않는다.
- 쿠키·`Authorization`·`Set-Cookie`는 **관측 로그에 기록하지 않는다** (금지 필드 화이트리스트 테스트).
- 관측 로그의 URL은 **정규화 저장**한다 (query·fragment 제거, scheme+host+path만).
- 세션은 실행 간 **재사용하지 않는다.** "지난번 통과한 쿠키를 다시 쓰기"는 명시적 금지다.

### A8 — 착수 전 정당화 검증 (게이트)

patchright는 anti-bot 탐지 회피를 목적으로 하는 패치다. "공개 정보 접근"과 "봇 탐지 회피"의
경계가 여기서 가장 얇다. **R3 착수 전에 A8을 판정하고, 정당화 불가로 결론나면 T2·T3를 삭제한다.**
그 경우 제품은 "HTTP 계층 한정 + 명확한 실패 보고"로 재정의되며, `browser_required`는
정상적인 미지원 분류로 남는다. 이것이 브라우저 폴백을 Must가 아니라 **Should**로 둔 이유다.

## 결과

**좋아지는 것**
- JS 챌린지 유형에서도 돌파 경로가 존재한다.
- 대다수 요청은 T1에서 끝나므로 평균 비용은 낮게 유지된다.
- 관측 로그가 단계별 성공률을 남겨, "T2/T3가 실제로 값을 하는가"를 수치로 판단할 수 있다.

**나빠지는 것 / 감수하는 것**
- 최초 T2 진입 사용자는 대용량 다운로드를 겪는다 (A5, 미검증 가정).
- 브라우저 의존성은 CI/헤드리스 환경에서 불안정할 수 있다.
  → 완화: T1만으로 도는 `--no-browser` 모드를 벤치에서도 별도 측정해, 브라우저 없는
  환경의 돌파율을 따로 보고한다.
- 3단 전부 시도 시 단건 지연이 수십 초까지 늘 수 있다. → `max_attempts`/`timeout`으로 상한.
- 기업 관리 장비에서 브라우저 런타임 설치가 정책상 차단될 수 있다 (A5).
  → **R3 배포 전 깨끗한 환경 설치 시험(SC-7)** 을 게이트로 둔다. 릴리즈 후 피드백으로 검증하지 않는다.

## 대안

- **T1만**: 기각 — JS 챌린지 유형이 구조적으로 막힌다.
- **브라우저 우선**: 기각 — 평균 비용이 폭증하고, 어떤 지문이 통했는지 학습되지 않는다.
- **T2만 (patchright 단일)**: 기각 — patchright 탐지 시 남는 수단이 없다. 사용자 결정은 "전 단계 허용".
