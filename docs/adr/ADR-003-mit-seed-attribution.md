# ADR-003: 원본(MIT) TLS 후보 리스트를 초기 시드로 사용

- 상태: Accepted
- 날짜: 2026-08-24
- 관련: NG-7, A4, SC-5

## 맥락

`fivetaku/insane-search`(MIT)의 `waf_profiles.yaml`에는 벤더별
`tls_impersonate_candidates` / `avoid` 리스트가 들어 있다. 이는 실측으로 얻은
유일한 비자명 데이터다. 다만 원작자 스스로 "Refresh quarterly" 주석을 달아 두었다 —
**분기 단위로 낡는 데이터**라는 뜻이다.

이것을 어떻게 다룰지가 프로젝트 성격을 정한다. 전부 베끼면 3개월짜리 자산을 얻고
그 뒤엔 다시 원본을 봐야 한다. 아예 안 쓰면 첫 벤치가 무의미하게 낮게 나와
A1 검증이 왜곡된다.

## 결정

**리스트를 "출발 좌표"로만 쓰고, 자산으로 취급하지 않는다.**

1. 엔진 코드는 100% 자체 구현한다 (NG-7). 이식하는 것은 공개된 측정 결과 값뿐이다.
2. `profiles.yaml` 최상단과 `NOTICE` 파일에 MIT 출처와 원문 라이선스를 명시한다.
3. 시드 값에는 `seeded_from: insane-search@<commit>` / `last_reviewed: <date>` 필드를 붙인다.
4. **첫 벤치에서 시드 값의 유효성을 실측 대조한다** (A4 검증).
5. `refresh` 서브커맨드가 벤치 결과로 리스트를 갱신하면, 시드 표기는 자동으로 소멸한다 (SC-5).

## 결과

**좋아지는 것**
- 첫 벤치가 합리적 기준선에서 출발해 A1/A2 검증이 유효해진다.
- 라이선스·출처가 명시되어 MIT 조건을 충족한다.
- 시간이 지나면 시드가 자연히 자체 측정값으로 대체된다 — 종속이 자동 해소된다.

**나빠지는 것 / 감수하는 것**
- 초기 리스트가 이미 낡았다면 첫 수치가 실제보다 낮게 나온다.
  → 이것이 A4를 첫 벤치에서 검증하는 이유다.
- "결국 베낀 것 아니냐"는 인식 리스크. → NOTICE와 코드 자체 구현으로 대응한다.

## 대안

- **전부 자체 측정으로 시작**: 기각 — 초기 수치가 왜곡되고 착수가 느려진다.
  (단, `refresh` 1주기 후에는 사실상 이 상태가 된다.)
- **원본 YAML 파일 자체를 벤더링**: 기각 — 갱신 책임이 원본에 남고, NG-7 취지에 어긋난다.
