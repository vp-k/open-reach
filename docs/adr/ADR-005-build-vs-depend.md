# ADR-005: 원본에 의존하지 않고 자체 구현한다

- 상태: Accepted
- 날짜: 2026-08-24
- 관련: NG-7, ADR-003, SC-1
- 배경: codex 검토 [MAJOR] "원본 유료화는 사용자 문제가 아니라 조달 리스크다" 반영

## 맥락

`fivetaku/insane-search`(MIT, 2.4k★)는 지금 이 문제를 상당 부분 해결한다.
따라서 첫 질문은 "어떻게 만들 것인가"가 아니라 **"왜 만드는가"** 다.

세 가지 선택지가 있었다.

1. **원본을 그대로 쓴다** — 즉시 동작. 다만 유료화 계획이 공표돼 있어, 우리 리서치 능력이
   타인의 가격 정책에 종속된다. 유료화 시점·조건·기존 사용자 처우는 우리가 통제할 수 없다.
2. **로컬 미러/벤더링** — 유료화 시점의 스냅샷을 보존. 그러나 유지 책임만 떠안고 개선은 멈춘다.
   원작자가 "Refresh quarterly"라 적은 데이터는 3개월이면 낡는다. 라이선스는 MIT라 허용되지만
   **미러는 자산이 아니라 부채**다.
3. **자체 구현** — 초기 비용이 크다. 대신 접근 능력의 유지·개선 주도권을 갖는다.

## 결정

**3을 택한다.** 단, 이 결정은 "원본보다 잘 만들 수 있다"는 주장이 아니다.
**"측정 가능한 형태로 유지할 수 있다"** 는 주장이다.

- 엔진 코드는 100% 자체 구현한다 (NG-7).
- 원본에서 가져오는 것은 공개된 **측정 결과 값**뿐이며 출처를 명시한다 (ADR-003).
- 원본이 MIT로 열려 있는 동안 **대조 측정을 확보한다** (SC-1, Round 1).
  이것이 원본 대조를 R4가 아니라 R1에 둔 이유다.

## 결과

**좋아지는 것**
- 유료화·아카이브·정책 변경에 영향받지 않는다.
- 우리 사용 맥락(Claude Code 플러그인, devncat 마켓플레이스)에 맞춘 인터페이스를 가진다.
- 돌파율이 우리 계측 체계 안에 들어와, 개선과 회귀가 관측된다.

**나빠지는 것 / 감수하는 것**
- 초기 몇 달간 원본보다 낮은 돌파율을 감수한다. SC-1의 합격선을 `× 0.9`로 둔 이유다.
- 유지 책임이 전적으로 우리에게 온다. → SC-5(자동 갱신)와 `last_reviewed` 경고가 대응.
- "왜 있는 걸 다시 만드나"는 비판은 유효하다. **A0(문제 규모) 검증에서 실패율이 10% 미만으로
  나오면 이 ADR을 철회하고 프로젝트를 중단한다.**

## 재검토 조건

- A0 실패율 < 10% → 프로젝트 중단
- R1 종료 시 원본 대비 돌파율 < 50% → 자체 구현 접근법 재설계
- 원본이 영구 무료를 공표 → 본 ADR을 Superseded로 전환하고 원본 사용을 재검토
