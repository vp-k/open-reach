# 정책 경계 (Policy Boundaries) — open-reach

> **이 문서의 목적**: "무엇을 하지 않는가"를 선언으로 끝내지 않고, **각 경계마다 코드 안의 강제 지점과 그것을 증명하는 테스트**를 1:1로 대응시킨다.
> 강제 수단이 없는 경계는 경계가 아니라 희망이다. 이 표에서 "강제 지점" 칸이 비어 있는 행은 존재할 수 없다.

**적용 범위**: `overview.md`의 NG-1 부터 NG-13, `docs/SPEC.md`의 Constraints(보안 절), ADR-006의 A8 판정 기준.

---

## 1. 경계 원칙

| ID | 원칙 | 이것을 위해 포기하는 것 |
|----|------|------------------------|
| P-B1 | **인증된 콘텐츠에는 손대지 않는다.** 로그인·결제로 보호된 것은 감지하고 보고할 뿐 넘지 않는다 | 로그인 뒤 자료를 요구하는 사용 사례 전부 |
| P-B2 | **사람인 척하지 않는다.** TLS·HTTP 계층의 표준 클라이언트 표현은 쓰되, 지속 신원과 행동 시뮬레이션은 만들지 않는다 | 행동 분석형 WAF 상대의 돌파율 |
| P-B3 | **자격증명을 만지지 않는다.** 받지도, 저장하지도, 읽지도 않는다 | 사용자 세션 재사용으로 얻을 수 있었던 접근 |
| P-B4 | **내부망으로 향하지 않는다.** 판정 불가는 차단으로 처리한다(fail-closed) | 사설망 내 문서 조회 |
| P-B5 | **조용히 실패하지 않는다.** 경계에 부딪히면 그 사실이 종료 코드와 분류로 드러난다 | "일단 뭐라도 반환"하는 편의성 |

## 3. SSRF 차단 체인 (fail-closed)

순서를 바꾸지 않는다. 각 단계는 **통과해야만** 다음 단계로 간다.

1. **스킴 allowlist** — `http` / `https` 외 전부 거부 (`file`, `ftp`, `data`, `gopher`, `ws` 포함).
2. **길이·형식 검증** — 2048자 초과, 파싱 실패 URL 거부.
3. **DNS 해석** — 해석된 모든 A/AAAA 레코드를 검사한다. 해석 결과가 나왔는데 대역 판정이 불가능하면 **차단**(허용 아님)한다. 반면 조회 자체가 NXDOMAIN·타임아웃으로 실패해 검사할 주소가 없는 경우는 연결을 시도하지 않되 `policy_blocked`가 아니라 `network`(exit 1)로 분류한다 — 정책 위반이 아니라 도달 불가이기 때문이다 (AC-B-002-3).
4. **주소 대역 차단** — RFC1918(10/8, 172.16/12, 192.168/16), 루프백(127/8, `::1`), 링크로컬(169.254/16, `fe80::/10`), CGNAT(100.64/10), IPv6 ULA(`fc00::/7`), 미지정(`0.0.0.0`, `::`).

   > **테스트 픽스처 예외 (유일)**: `OPENREACH_FIXTURE_BASE`가 설정된 경우 그 값의
   > `scheme://host:port`와 **완전히 일치하는** 오리진만 이 대역 차단에서 제외한다.
   > 포트가 다른 루프백(`127.0.0.1:1` 등)은 계속 차단되고, 리디렉션 각 홉에도 같은
   > 완전 일치 규칙으로 판정하며, 메타데이터 주소 명시 차단이 항상 우선한다.
   > 변수가 없으면 예외는 존재하지 않는다 (SPEC Constraints 보안 절).
5. **메타데이터 주소 명시 차단** — `169.254.169.254`, `metadata.google.internal`, `100.100.100.200`.
6. **리디렉션 매 홉 재검사** — 3~5단계를 **모든 홉에서 반복**한다. 최대 홉 5, 초과 시 `policy_blocked`.

**판정 불가 = 차단.** 이 원칙을 완화하는 CLI 플래그는 제공하지 않는다. 위의 픽스처 오리진 예외가 유일하며, 그것은 인수 테스트 전용 환경변수로만 활성화되고 오리진 완전 일치에만 적용된다.

## 4. A8 판정 기준 (브라우저 티어 존치 심사)

ADR-006에서 확정한 4항이다. **하나라도 해당하면** 브라우저 티어(T2/T3)를 삭제하고 제품을 "HTTP 계층 한정 + 명확한 실패 보고"로 재정의한다.

| # | 부정 조건 | 판정 방법 |
|---|-----------|----------|
| A8-1 | 실행 간 신원이 지속되는가 (쿠키·프로필·스토리지 재사용) | 소스 검사 + 두 번 실행 후 프로필 디렉토리 잔존 여부 |
| A8-2 | 사람의 행동을 흉내내는가 (마우스 궤적·타이핑 지연·랜덤 스크롤) | 소스 검사 |
| A8-3 | 사용자 자격증명이나 쿠키를 취급하는가 | 소스 검사 + CLI 옵션·환경변수 목록 |
| A8-4 | 성공 지표에 "탐지 회피도"가 포함되는가 | `bench` 출력 필드 검사 (탐지 회피 관련 지표 부재) |

**심사 시점**: R3 착수 직전 1회, 그리고 브라우저 관련 코드 변경 시마다.

## 5. robots.txt 취급 — R6 개정 (사용자 승인, 2026-09-02)

**결론부터: 기본값은 미조회다.** robots.txt 는 이 도구에서 더 이상 경계가 아니라 **모드**다 (SPEC AC-B-003-6).

| 모드 | 동작 | 켜는 법 |
|------|------|---------|
| `off` (**기본**) | `robots.txt` 를 **조회하지 않는다** — 요청 0건. `Disallow` 경로도 취득한다 | 기본값 |
| `advisory` | 조회하되 차단하지 않는다. 오리진당 1회 stderr 로 보고한다 | `--robots advisory` |
| `enforce` | `Disallow` 면 `policy_blocked`(`rule="robots"`)로 중단. R5 까지의 동작 | `--respect-robots` |

- **"무시"가 아니라 "미조회"다.** 판정을 받아 놓고 버리는 구현은 이 약속을 어긴다 — 요청이 나가면 상대 서버는 이미 그것을 봤다. `policy.robots_gate` 의 `off` 분기는 네트워크에 나가지 않으며, 리디렉트 홉에서도 `hop_guard_for("off")` 가 robots 코드 경로가 **없는** 가드(`ssrf_hop_guard`)를 돌려주므로 샐 자리가 구조적으로 존재하지 않는다. 검증은 히트 수 0 으로 한다 (us-b-003, us-b-010).
- `enforce` 에서 `robots.txt` 조회 자체가 실패(404·타임아웃)하면 해당 호스트의 기본 정책(허용)을 따르되, 그 사실을 관측에 남긴다 — 조회 실패를 차단으로 처리하면 대다수 정상 사이트가 막히므로, 여기서는 fail-open 이 의도된 예외다. 이 예외는 **SSRF 체인에는 적용되지 않는다.**
- **왜 뒤집었나.** 잔여 도달력 격차의 실질 전부가 자발적 robots 준수였다(`docs/r1-report.md`: 원본 64/70 vs open-reach 60/70 — 격차 4건 중 robots 자발 포기 2건, 성공 정의 차이 2건, **실제 돌파력 격차 0건**). 사용자 승인 아래 도달력을 택했다.
- **함께 남겨야 할 사실.** robots 는 법이 아니지만 사이트가 명시한 의사다. 일부 사이트는 AI/RAG 접근을 명시적으로 거부하며, 기본 모드는 그것을 알고 지나간다. 이 문서가 "윤리 경계로서 robots 를 존중한다"고 계속 적어 두면 문서가 거짓말이 되므로 그 표현은 삭제했다 (NG-8 정신).
- **robots 와 함께 완화되지 **않는** 것.** 신원 위장(NG-13)·SSRF(NG-11)·로그인월/페이월(NG-1·2)·CAPTCHA(NG-3)·프록시 로테이션(NG-6)은 그대로다. 특히 특정 AI UA 만 허용하는 곳에 그 UA 를 참칭하는 경로는 도입하지 않는다 — robots 를 안 보는 것과 신원을 속이는 것은 다른 일이다.
- **속도도 완화하지 않는다.** 호스트당 동시성 1 과 최소 간격 하한(`MIN_HOST_INTERVAL_S = 1.0`)은 모드와 무관하게 유지된다. robots 를 안 본다고 상대 서버를 두드리는 속도까지 올리지는 않는다.
  - ⚠️ 개정 전 이 자리에는 "`Crawl-delay` 지시가 있으면 호스트 최소 간격의 하한으로 사용한다"고 적혀 있었으나, **그 동작은 코드에 구현된 적이 없다**(`Crawl-delay` 는 소스 어디에도 등장하지 않는다). 문서만의 주장이었으므로 삭제한다. 따라서 `off` 전환으로 잃는 간격 신호도 없다 — 하한은 처음부터 `MIN_HOST_INTERVAL_S` 하나였다.

## 6. 이 문서의 개정 규칙

- 경계를 **추가**하는 개정은 자유롭게 한다.
- 경계를 **완화·삭제**하는 개정은 사용자 승인 없이 하지 않는다. 승인 시 `overview.md` 변경 이력과 이 문서 양쪽에 사유를 남긴다.
- 표의 "강제 지점"이 비어 있는 상태로 커밋할 수 없다 — 강제 없는 선언은 이 문서에 들어오지 않는다.
